# QA Checklist

Tick an item only when you checked it. Write "not checked" where you did not.

## Human authorship
- [ ] The human wrote their own ideas, one true detail and the must-nots before seeing AI output
- [ ] The human chose or mixed a direction (or the result is labelled "agent-picked, not human-reviewed")
- [ ] The human wrote the headline, first sentence, primary button and one personal line
- [ ] The process note separates human decisions from AI work

## Specificity
- [ ] 8 or more brief-specific facts were listed; assumptions marked
- [ ] The idea sentence passes the competitor test
- [ ] Every major choice (display face, ground and accent, layout motif, imagery, live thing) maps to a brief fact or a functional reason
- [ ] No banned default replaced by its popular substitute
- [ ] Nothing invented: no logos, clients, quotes, ratings, numbers or claims; sample content listed for confirmation

## Distinctiveness and substance
- [ ] slop-check run; tier and each finding reviewed (reflex or decision)
- [ ] The first screen could not belong to a competitor
- [ ] One live thing exists and works on a phone
- [ ] Every section the brief needs has its full content; no thin or empty screens
- [ ] Neighbouring sections use different compositions

## Visual quality
- [ ] One dominant thing per screen; clear second and third levels
- [ ] Headlines two lines or fewer at 1440, 768 and 390 px
- [ ] Strong type scale, five sizes or fewer, two families at most, fonts actually load
- [ ] Colour strategy chosen; roles as tokens; contrast checked on real backgrounds
- [ ] Spacing has rhythm; equal outer margins; two or three shared left edges
- [ ] Browser surfaces themed (selection, caret, focus)

## Function
- [ ] Main journey tested end to end
- [ ] Every visible link and button works or is clearly decorative
- [ ] Loading, empty, error, success and validation states where relevant
- [ ] No console errors; build and lint run if present

## Responsive and accessible
- [ ] render-check at 1440, 768, 390: 0 FAIL (or each FAIL explained)
- [ ] No horizontal scroll; phone layout is its own composition
- [ ] Keyboard navigation with visible focus
- [ ] Labels, alt text, heading order, title, lang
- [ ] Reduced motion respected; content visible without scripts

## Delivery
- [ ] Opens from a clean start; the command, file or URL is written down
- [ ] Known-good copy saved
- [ ] Every check not run is listed
